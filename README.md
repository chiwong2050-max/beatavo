# Beatavo

A fast, family-safe dance-video web app. People watch and play along with fun cartoon
music videos hosted on YouTube. Videos are grouped into two sections:

- **Beatavo** — the main catalogue
- **Beatavo Kids** — kid-friendly picks

There is **no backend and no framework** — just static HTML, CSS and vanilla JavaScript.
It is designed to be mobile-first, clutter-free and quick to load.

Highlights:

- A **"Dance of the day"** hero that picks the same video for everyone each day.
- **Category pages** driven by an optional `tags` field (`/tag/?t=animals`).
- A **Dance challenge** mode: five random songs back to back with a 3-2-1 countdown.
- **Share** (Web Share API with a copy-link fallback) and **Embed** (a copyable iframe
  snippet pointing at a minimal `/embed/` player) — no third-party scripts.
- **Playlists** — build named lists saved in `localStorage` and play a whole list
  continuously from `/playlists/`.
- A **"Recently played"** row on the home page (the last 12 videos opened).
- A **"Favourites"** page (`/favourites/`) with your saved dances **and** a
  **"Your top dances"** list built from a private, on-device play tally.
- A **"Up next"** panel on the watch page: the next 5 videos, reorderable with arrow
  buttons and removable from the queue.
- A **"More like this"** row under each video (shared tags first, then the same section).
- Auto-built **home page sections per tag** (any tag with 3+ videos, e.g. Animals, Party,
  Robots).
- A **light/dark theme toggle** that follows `prefers-color-scheme` by default and
  remembers your choice.
- A **Kids mode lock** that keeps the app on `/kids/`, unlocked by a grown-up maths
  question.
- **Keyboard shortcuts** on the watch page (space / N / S / F) with a `?` help popup.
- **Offline support** — the service worker caches the app shell and the pages you have
  viewed, and a friendly [`offline.html`](offline.html) lists what you played recently.
- A dismissible **"Add to home screen"** banner (remembered in `localStorage`).
- A **sleep timer** (15/30/60 min) and a **Loop this video** toggle on the watch page.
- A friendly **404 page** with a **Play something random** button.

## Tech stack

| Area | Choice |
| --- | --- |
| Markup | Static HTML5 |
| Styling | Plain CSS (custom properties / design tokens, light + dark) |
| Behaviour | Vanilla ES modules |
| Video | YouTube IFrame API via the privacy-enhanced `youtube-nocookie.com` player |
| PWA | `manifest.json` + a service worker that caches the app shell |
| Build | None (icons are generated by one small Node script) |
| Hosting | Any static host (GitHub Pages, Netlify, Vercel, S3, …) |

No API keys, secrets or trackers are used anywhere in the code.

## The video catalogue

Videos are read at runtime from [`data/videos.json`](data/videos.json). Each entry is:

```json
{
  "id": "dQw4w9WgXcQ",
  "title": "Funky Robots Dance Along",
  "section": "main",
  "published": "2026-01-05",
  "tags": ["robots", "party"]
}
```

- `id` — the YouTube video id (the part after `watch?v=`).
- `section` — either `"main"` or `"kids"`.
- `published` — an ISO date. The grid always sorts **newest first**.
- `tags` — **optional** list of categories (lowercase, e.g. `animals`, `party`,
  `kids-favourites`). They drive the category pages and the "Browse by tag" chips.
  A tag only gets its own page once it has **at least 3 videos** — smaller tags are
  hidden rather than shown as near-empty pages.

> **The committed `data/videos.json` contains six clearly-marked `[SAMPLE]` entries
> with placeholder ids.** It exists so the app runs out of the box.
>
> In production this file **will be generated by a server script** (for example, a
> scheduled job that pulls a channel/playlist from the YouTube Data API and writes
> this JSON). Keep that script server-side: **never put a YouTube API key in this
> front-end repository.**

## Features

- **Dance of the day** — the home hero picks a video deterministically from the UTC
  calendar date, so every visitor sees the same pick each day (no storage, no
  randomness).
- **Category pages** (`/tag/?t=<tag>`) — each has its own `<title>`, meta description
  and Open Graph tags, plus a **Play all** button that keeps playing inside that
  category.
- **Dance challenge** (`/challenge/`) — plays **5 random videos** back to back with a
  "Get ready" 3-2-1 countdown between songs and a "You danced 5 songs!" finish screen.
  No accounts: the only thing stored is a local streak counter
  (`beatavo:challenge-streak` in `localStorage`), which advances once per day.
- **Share** — the watch page's Share button opens the native share sheet where
  available, and otherwise copies the canonical link.
- **Embed** — the watch page's Embed button copies an `<iframe>` snippet that points
  at the minimal `/embed/?v=ID` player, which is `noindex` and free of site chrome.
- **Playlists** — every card and the watch page carry an **Add to playlist** button
  that opens a shared dialog (create, tick/untick, delete). Playlists are saved under
  `beatavo:playlists` in `localStorage`. `/playlists/` lists them all and **Play all**
  opens `/watch/?v=ID&playlist=<id>`, so the watch page queues the whole list and plays
  it continuously (the `playlist` param takes priority over `tag`/section queues).
- **Recently played** — the watch page records each video opened under
  `beatavo:recently-played` (deduped, capped at the last **12**), and the home page
  shows a horizontally-scrolling "Recently played" row when there is history.
- **Up next queue** (watch page) — the panel lists the **next 5** videos in the queue
  with arrow buttons to move an item up or down and a button to remove it. Reordering
  never moves an item above the one currently playing.
- **More like this** — under the player, a row of recommendations chosen by shared tags
  first, then by the same section, all from the current catalogue.
- **Home page tag sections** — the home page builds one horizontal row per tag that has
  **3 or more videos** straight from `data/videos.json` (the same threshold as the tag
  pages and the sitemap), each with a **See all** link to `/tag/?t=<tag>`.
- **Favourites page** (`/favourites/`) — your saved dances plus a **"Your top dances"**
  list, ranked from a **private, on-device play tally** (`beatavo:plays`, which counts a
  video once each time playback actually starts). Nothing is sent anywhere.
- **Light/dark theme** — the header toggle pins a choice in `beatavo:theme`; otherwise the
  theme follows the operating system. A tiny inline script sets it before first paint so
  there is no flash of the wrong theme.
- **Kids mode lock** — the header toggle stores `beatavo:kids-mode`; while it is on,
  every other page redirects to `/kids/` on load. On the kids page a **Grown-ups: exit**
  button opens a simple addition question, and only a correct answer clears the lock.
- **Keyboard shortcuts** (watch page) — `Space` play/pause, `N` next, `S` shuffle the
  queue, `F` fullscreen, `←`/`→` previous/next, and `?` opens a small help popup. Keys
  are ignored while typing in a field or when a modifier is held.

## Stored data

Everything is client-side; there is no account and no server. These `localStorage`
keys are the only state:

| Key | Purpose |
| --- | --- |
| `beatavo:favourites` | Hearted video ids |
| `beatavo:playlists` | Named playlists and their video ids |
| `beatavo:recently-played` | The last 12 videos opened on the watch page |
| `beatavo:plays` | Private per-video play tally (powers "Your top dances") |
| `beatavo:theme` | Pinned light/dark theme (absent = follow the system) |
| `beatavo:kids-mode` | `1` while the kids lock is on |
| `beatavo:install-dismissed` | `1` once the install banner is dismissed |
| `beatavo:challenge-streak` | Dance-challenge day streak |
| `beatavo:lang` | Chosen interface language |

## Local preview

The app needs to be served over HTTP (not opened as a `file://` path) because it uses
ES modules, `fetch()` and a service worker.

Using the bundled dependency-free server:

```bash
npm start
# → Beatavo is running at http://localhost:4173/
```

Or with any other static server, e.g.:

```bash
npx --yes serve -l 4173 .      # Node
python -m http.server 4173     # Python 3
```

Then open <http://localhost:4173/>. Try:

- The **Play all** and **Shuffle play** buttons, the **Beatavo / Beatavo Kids / Favourites**
  tabs, and the **search** box (filters by title).
- The **Dance of the day** hero, the **Browse by tag** chips, and the auto-built
  **per-tag home sections**, which link to `/tag/?t=animals`, `/tag/?t=party`,
  `/tag/?t=kids-favourites`, and so on.
- `/challenge/` for the five-song dance challenge, with a 3-2-1 countdown and a local
  streak counter.
- Tapping the **heart** on any card saves it to **Favourites** (stored in `localStorage`,
  no account needed); `/favourites/` gathers the saved dances and shows **"Your top
  dances"** once you have played a few.
- The **theme toggle** in the header — flip it to light or dark and reload; your choice
  sticks (and with no choice saved, the theme follows your system setting).
- `/kids/` for a stripped-back kids-only page with extra-large buttons.
- Opening a video to land on `/watch/?v=VIDEO_ID` — the title, description and Open
  Graph tags update per video, so the link is shareable. The **Share** button uses the
  native share sheet or copies the link; **Embed** copies an `<iframe>` snippet.
- The **"Up next"** panel: use the ↑/↓ buttons to reorder the next 5 videos and the ✕
  button to drop one; the **"More like this"** row beneath the player suggests what to
  watch next.
- **Next / Previous** (and the ← / → arrow keys) for continuous play — when a video
  ends the next one starts automatically. Scroll away and a **mini player** sticks to
  the bottom with play/pause, next/previous and an expand button.
- The watch page's **sleep timer** (pauses playback after 15/30/60 minutes) and the
  **Loop this video** toggle.
- **Offline mode** — after visiting a few pages, stop the server (or go offline) and
  reload: the service worker serves the shell and shows [`offline.html`](offline.html)
  with your recently played titles. (In the browser's DevTools you can also tick
  **Offline** under Network → it simulates the same thing.)
- Any unknown URL, e.g. <http://localhost:4173/nope>, for the **404 page** and its
  **Play something random** button.
- The **language picker** in the header.

## Multi-language UI

UI strings live in [`i18n/`](i18n) as one JSON file per locale:

`en`, `es`, `pt`, `fr`, `zh-Hans` (Chinese, Simplified), `hi`, `ar` (right-to-left) and `id`.

- [`assets/js/i18n.js`](assets/js/i18n.js) auto-detects the browser language (matching
  BCP-47 tags such as `pt-BR` → `pt`) and falls back to English for any missing key.
- A saved choice wins and is stored under `beatavo:lang`; the header picker switches
  locales and reloads.
- Arabic sets `dir="rtl"` on the document.
- **Video titles stay exactly as authored** — only the interface is translated.

To add a language, drop a new `<code>.json` in `i18n/` (copy `en.json` and translate)
and add its entry to `LOCALES` in `assets/js/i18n.js`.

## Search engine bits

- `sitemap.xml` and `robots.txt` are generated from the catalogue:

  ```bash
  npm run sitemap                        # uses the default production origin
  SITE_URL=https://example.com npm run sitemap
  ```

  The sitemap lists the home, kids, challenge, about and privacy pages, **one URL per
  `/watch/?v=ID` page**, and **one URL per category** (`/tag/?t=<tag>`) for every tag
  with at least 3 videos. Re-run it whenever `data/videos.json` changes. The
  `/playlists/` and `/favourites/` pages are deliberately **`noindex`** (their content is
  per-user), so they are left out of the sitemap.
- The home page carries **schema.org `WebSite`** JSON-LD, and each watch page injects
  **`VideoObject`** JSON-LD (name, description, thumbnail, upload date, embed URL) for
  rich search results.

## PWA

- [`manifest.json`](manifest.json) declares the app name **Beatavo**, a bright violet
  theme colour (`#7c4dff`) and the generated icons.
- [`sw.js`](sw.js) pre-caches the **app shell** (HTML, CSS, JS, the i18n files, icons,
  manifest) so the app opens instantly and works offline for browsing. **Videos are not
  cached** — all YouTube/`ytimg.com` requests are left untouched.

Regenerate the icons after changing the generator:

```bash
npm run icons
```

## Accessibility & performance notes

- Semantic landmarks, a skip link, and the WAI-ARIA tabs pattern with arrow-key support.
- Large tap targets (≥48px), visible focus rings, and `prefers-reduced-motion` support.
- Light and dark themes via `prefers-color-scheme`, with a header toggle that remembers
  your choice (`beatavo:theme`). Text and icons meet **WCAG AA** contrast in both themes.
- Every icon-only button (theme toggle, queue reorder/remove, loop, share, hearts, mini
  player, dialogs) carries an `aria-label`, and the theme toggle exposes its state with
  `aria-pressed`.
- No render-blocking third-party resources: the YouTube iframe is only loaded **after**
  a click (thumbnail "facade" pattern), which keeps the initial page fast.
- `preconnect` hints to `https://i.ytimg.com` on every page so thumbnail images start
  their connection early.
- Dialogs (playlist picker, grown-up gate, shortcut help) use `role="dialog"` +
  `aria-modal`, trap Tab focus, close on `Escape`, and restore focus on close.
- Thumbnails use native `loading="lazy"` + `decoding="async"` (the queue and grid);
  the above-the-fold facade image is fetched eagerly with `fetchpriority="high"`.
- Images carry explicit `width`/`height` to avoid layout shift.

## Deploying

Because it is a static site, deploy the repository root as-is:

- **GitHub Pages** — Settings → Pages → deploy from the `main` branch (root).
- **Netlify / Vercel** — publish directory `.`, no build command.

The site uses relative paths, so it works both at a domain root and in a sub-path.
(The two exceptions are [`404.html`](404.html) and [`offline.html`](offline.html), which
are served at arbitrary URLs and therefore use root-relative `/…` paths — host them at
the domain root.) Set your real domain in the canonical/`og:url` values if you use a
custom domain, and regenerate the sitemap with `SITE_URL=https://your-domain npm run sitemap`.
